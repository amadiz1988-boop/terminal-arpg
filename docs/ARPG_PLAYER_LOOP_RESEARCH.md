# ARPG 玩家循環研究

更新日期：2026-09-05

這份文件回答一個實際問題：玩家開一張圖以後，下一張圖為什麼還想繼續？研究範圍包括 Path of Exile 官方系統說明、火炬之光：無限官方賽季資料，以及創作者的實際刷圖、製裝與新手流程影片。版本細節會改動，本文只保留能跨賽季使用的設計結論。

## 看過的實際遊玩內容

### Path of Exile

1. Zizaran 的 [Early Mapping 完整新手流程](https://www.youtube.com/watch?v=TMI0ohmBhDQ)。影片從新聯盟的早期地圖開始，實際處理 Atlas 推進、地圖維持、掉落篩選、Build 補強與下一張圖的選擇。這段內容證明新手需要一條看得見的進度線，以及每次卡關時可執行的補強方向。
2. Empyriangaming 的 50 張八詞綴 Beach Harbinger 測試。創作者固定地圖、怪群規模、Scarabs 和 Atlas 配置，記錄成本、完成時間、掉落及每小時收益。重點是先提出 farming hypothesis，再跑一批樣本驗證。參考：[影片摘要與時間軸](https://www.yeschat.ai/blog-8mod-mapping-with-harbingers-atlas-strategies-based-or-cringe-poe-875-51934)。
3. Mathil 的 [長期 Build 清單](https://www.pathofexile.com/forum/view-thread/3298972)。其創作循環集中在提出新 Build、買或做關鍵裝備、實戰刷圖、打王驗證，再換下一個構想。觀眾看的核心是 Build 是否成立，以及實戰手感和限制。

### 火炬之光：無限

1. Milkybk_ 的 [Farming the Endgame](https://www.youtube.com/watch?v=gzlYWi6fuAg)。影片比較四種 Trait Deck，分別追求基礎收益、Ember、傳奇裝備與賽季內容。玩家先選產業，再選對應內容，而非只選難度倍率。
2. Gooba03 的 [Endgame Crafting 實錄](https://www.youtube.com/watch?v=6Oud9xlm-M8)。時間軸包含買底材、目標製作、資源耗盡、失敗後改走其他製作路線。製裝的張力來自可控目標、材料成本與失敗後的調整。
3. 官方 SS6 說明記錄了可選詞綴池、加入或替換詞綴，以及高階材料才能存取高階池的設計。參考：[SS6 官方頁面](https://torchlight.xd.com/us/ep8)。
4. 官方 SS13 把部分傳奇裝備綁定在指定玩法和難度，並提供中後期插槽與詞綴追求。參考：[SS13 官方更新](https://torchlight.xd.com/ss13pn/?lang=en)。

## 玩家實際在做什麼

觀察到的短循環如下：

1. 選 Build 當前缺口，例如清圖、單體、生存或移速。
2. 選能產出該缺口所需資源的地圖與玩法。
3. 投入地圖、通貨或玩法材料，提高風險與預期收益。
4. 連刷一批內容，過程中只撿符合篩選條件的東西。
5. 批次結算收益，保留底材、出售商品、分解垃圾。
6. 買裝、製裝或調整技能，再測一次速度和可承受難度。

PoE 官方 Atlas 被動樹讓玩家增加指定機制的出現率、怪量與獎勵，等於選擇自己的刷圖產業。參考：[Atlas 被動樹官方揭露](https://www.pathofexile.com/forum/view-thread/3229978)。官方物品篩選器能依稀有度、物品等級、底材、詞綴與地圖 Tier 顯示或隱藏掉落，表示高掉落量必須配套降低判讀成本。參考：[PoE Item Filter](https://www.pathofexile.com/item-filter/about)。

## 玩家長期追求

長期目標可分成五類：

| 追求 | 玩家可觀察的進展 | 失去它的結果 |
| --- | --- | --- |
| Build 成形 | 關鍵技能、傳奇或詞綴逐件就位 | 裝備只剩數字大小 |
| 效率提升 | 每張耗時、每小時收益、死亡率改善 | 自動刷圖沒有優化題目 |
| 內容征服 | Atlas、Tier、首領與高風險內容解鎖 | 難度只剩線性倍率 |
| 財富累積 | 能購買或製作下一件關鍵裝備 | 通貨沒有用途 |
| 新構想驗證 | 換技能或裝備後，實戰結果明顯不同 | Build 選擇只是換名字 |

官方資料也支持這個結構。PoE 的挑戰聯盟提供新經濟、挑戰與重新開始的理由；Atlas 讓玩家專精地圖內容；Boss 邀請和高階掉落提供階段終點。參考：[Sentinel 官方更新](https://www.pathofexile.com/forum/view-thread/3264788/page/1)、[Echoes of the Atlas](https://www.pathofexile.com/echoes)。

## 實況主與內容創作者在做什麼

創作者的行為可以整理為四種節目：

* 聯盟起步：用低成本 Build 盡快進圖，記錄何時換技能、武器與防禦。
* Farming 實驗：先公開投入與策略，連跑 20 至 100 張，再計算淨收益和每小時效率。
* Build 實驗：提出一個機制組合，取得關鍵裝備，實測清圖與首領，再承認弱點。
* 製裝過程：選底材、設定必要詞綴、消耗材料、遇到失敗，決定停手或繼續投入。

這些內容都有可驗證的問題。觀眾會等答案，因此重複刷圖仍有張力。單純播放戰鬥文字沒有待驗證的問題，很快就會失去注意力。

## 對 Terminal ARPG 的研發約束

接下來的功能必須服務以下核心：

1. 每次開始前，玩家要選一個可說清楚的目標，例如找武器、囤製裝材料或取得首領碎片。
2. 每種 farming 路線要改變產物、風險、適合的 Build 和結算方式，不能只改倍率。
3. 每 3 至 6 張圖要出現一次可比較的決策，例如三選一戰利品、是否追加投資、製裝或換裝。
4. 掉落量增加時，判讀成本必須下降。升級品置頂、自動分解和保護規則屬於核心功能。
5. Build 關鍵裝備要有來源、進度與替代品。預設 Build 只提供路線，玩家仍從零取得內容。
6. 通貨與分解材料必須能換成可感知的成長，並且存在機會成本。
7. 測試以批次歷程為單位。每個候選版需模擬至少 30 分鐘等價流程，再抽查實際操作。

## 30 分鐘等價驗收

以一張地圖 35 至 55 秒的設計值計算，30 分鐘等價測試至少執行 40 張地圖。測試必須記錄：

* 地圖成功與死亡次數
* 玩家可感知決策次數
* 裝備升級、材料消耗與目標里程碑
* 最長無新事件區間
* 是否出現資源歸零後無法恢復
* 至少一次策略切換或 Build 調整

評分共 10 分：決策密度 2 分、回饋節奏 2 分、Build 表達 2 分、追逐目標 2 分、重玩動機 1 分、穩定性 1 分。低於 7 分的版本維持開發狀態。

## PoEDB 與 TLIDB 資料研究

PoEDB 和 TLIDB 很適合查資料結構、詞彙和數值範圍。兩站都屬於社群資料庫；TLIDB 首頁明確標示資料來自測試版本且與 XD 無關。涉及正式平衡時仍以遊戲內說明及官方更新為準。

### 屬性與傷害管線

PoEDB 的機制頁將攻擊與法術拆開。攻擊以武器傷害為基礎，法術以技能寶石為基礎；同類 Increased 先加總，不同 More 各自相乘。參考：[PoEDB 遊戲機制](https://poedb.tw/tw/Game_mechanics)。我們採用以下資料管線：

```text
攻擊單次傷害 = (武器基礎傷害 + 附加傷害)
              × (1 + 同類 Increased 總和)
              × More 來源 A
              × More 來源 B

法術單次傷害 = 技能基礎傷害
              × (1 + 同類 Increased 總和)
              × 各個 More 來源

每秒輸出 = 單次傷害 × 有效施放頻率 × 命中率 × 暴擊期望值
暴擊期望值 = 1 + 暴擊率 × (暴擊倍率 - 1)
```

順序固定為：基礎值、附加值、轉換、增加、更多、暴擊、敵方承傷與抗性。每個修正都要保留來源、標籤、作用範圍與條件，UI 才能解釋裝備提升來自哪裡。

### 防禦管線

PoEDB 列出的護甲減傷公式會隨單次物理傷害變化，因此面板不能用一個固定百分比代表所有情況。生命與能量護盾也採先加固定值、再乘 Increased 的結構。抗性則直接降低對應類型傷害並受最大值限制。參考：[PoEDB 防禦公式](https://poedb.tw/tw/Game_mechanics)。我們的模擬器需保存敵方 Hit Size，才能比較護甲對小怪群和首領重擊的差異。

### 裝備與詞綴

[PoEDB 詞綴庫](https://poedb.tw/tw/Modifiers)依裝備類型、勢力與特殊來源拆分詞綴。[TLIDB 打造資料](https://tlidb.com/tw/Craft)同時呈現基礎、侵蝕、初階、進階、至臻、序列與傳奇來源。兩者共同顯示四個必要欄位：

```text
AffixDefinition
  statKey
  valueRange
  tier
  spawnTags
  itemLevelRequirement
  source
  affixGroup
```

`affixGroup` 用來阻止互斥詞綴同時出現，`spawnTags` 控制底材和技能流派能否取得。裝備生成只引用定義 ID；顯示名稱與數值格式放在內容層，避免公式依賴中文文字。

### 天賦

PoE 的天賦價值在路徑成本、群集與改規則關鍵天賦。火炬採多塊天賦板，第一塊限制基礎選擇，後續逐步開放，另有神格石板改造既有節點。參考：[TLIDB 天賦基礎規則](https://tlidb.com/tw/Basic_Rules)。我們採手機可讀的分層方案：

* 每次只顯示一塊 12 至 18 點的天賦板。
* 小點提供單純數值，核心點形成 Build 方向，關鍵點改變規則並附帶代價。
* 一鍵流派只標出建議路徑和下一點，玩家仍親自配置。
* 底層保留圖結構、前置節點與節點效果 ID，未來可擴成大型網路。

### 傳奇裝備

[PoEDB 傳奇物品說明](https://poedb.tw/tw/Unique_item)指出傳奇有固定名稱與預設詞綴，整體數值可以低於頂級稀有裝，主要價值是提供能圍繞它建構流派的獨特玩法。傳奇效果因此分成兩層：普通數值仍走 Modifier Engine；改規則效果使用明確的 Rule Hook，例如轉換傷害、修改技能行為、改變資源支付或解除上限。

```text
UniqueEffect
  hook
  condition
  parameters
  priority
  exclusivityGroup
```

傳奇不能只提供更大的傷害數字。每件候選傳奇必須讓至少一個技能、天賦或 farming 策略改變最佳選擇。

## 命名、劇情與公開發行界線

PoE 的專有角色、地名、劇情段落、物品名稱與敘述文字不直接搬入公開遊戲。研發時會抽取語感規則：流亡、禁忌文明、腐化、宗教權力、遠古災變與異界觀測，再建立自己的地名、派系和事件。機制通用詞如暴擊、抗性、前綴、後綴、天賦、技能標籤可直接使用。

命名對照會放在獨立內容表。公式只依賴穩定 ID，因此日後調整世界觀不會造成引擎重構。

## PoE 邏輯與火炬操作的混合規格

| 系統 | 底層 | 手機操作 |
| --- | --- | --- |
| 傷害 | PoE 式標籤、Increased、More、轉換與條件 | 面板先顯示結果，點開才看計算來源 |
| 詞綴 | 底材、詞綴池、階級、權重與互斥群組 | 選詞綴類別後一次打造，立即比較前後 |
| 天賦 | 圖結構、核心點、關鍵點與路徑成本 | 分板顯示、一鍵推薦下一點、免費預覽 |
| 傳奇 | 固定效果加 Rule Hook，優先改玩法 | 直接標示適用技能與取得來源 |
| 交易 | 可查精確詞綴與數值區間 | 物品頁直接查價，保存篩選，一鍵購買合格商品 |
| 背包 | Build 感知評估與保護規則 | 升級品置頂、滑動鎖定、批次分解 |

火炬官方 SS13 已加入物品提示直接查價、跨打造與天賦介面跳轉交易行，以及套用價格篩選後快速購買。參考：[SS13 Trade House 更新](https://torchlight.xd.com/ss13pn/?lang=en)。SS6 也提供手機按鍵大小、位置與透明度調整，以及詞綴來源查詢。參考：[SS6 官方頁面](https://torchlight.xd.com/us/ep8)。這些操作原則會進入我們的手機介面驗收。
