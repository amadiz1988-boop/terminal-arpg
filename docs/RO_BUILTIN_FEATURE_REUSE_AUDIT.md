# RO 內建功能重用查核

更新日期：2026-09-11

## 決策原則

新增功能先查 rAthena、OpenKore、台灣官方客戶端資料與封包版本。原生功能可覆蓋需求時，玩家網頁只提供型別化白名單介面與即時狀態，不建立第二套規則。原生功能與產品需求有差距時，差距、來源與決策先寫入文件，再開始實作。

## 排行榜

| 查核項目 | 來源 | 結論 |
| --- | --- | --- |
| 原生名聲榜 | `src/common/mmo.hpp` 的 `MAX_FAME_LIST=10`；`src/map/clif.cpp` 的鐵匠、鍊金術師與跆拳名聲列表 | 只覆蓋特定職業名聲前十名，無法直接滿足全職業 Base／Job 排行 |
| 全職業資料 | rAthena `char`、裝備、外觀及公會資料 | 採唯讀查詢投影建立各職排行榜與角色公開頁 |
| 公平與安全 | `web_account_flags.is_test` 與玩家介面安全邊界 | 固定排除測試帳號，只公開角色名稱、職業、等級、紙娃娃、裝備與公會 |

狀態：P1，先完成公開測試 P0 穩定性。

## 拍賣、寄售與玩家交易

| 功能 | rAthena 來源 | OpenKore 來源 | 採用方向 |
| --- | --- | --- | --- |
| Auction | `src/map/clif.cpp`、`src/char/int_auction.cpp`、`conf/inter_athena.conf` | `src/Commands.pm` 的 `auction`；`src/Network/Send.pm` 與 `Receive.pm` 的 auction 封包 | 先做端到端封包相容測試，再決定是否作為寄售主入口 |
| 露天商店 | `src/map/vending.cpp` | 商店、購買與玩家互動封包 | 保留原生價格、庫存、成交與 Zeny 規則 |
| 收購商店 | `src/map/buyingstore.cpp` | 收購商店封包 | 可作玩家指定收購入口 |
| 離線擺攤 | `conf/battle/feature.conf` 的 autotrade 設定 | OpenKore 角色端流程 | 驗證伺服器設定、登出存續與重登一致性後再開放 |
| 郵件／RODEX | `src/map/mail.cpp`、`src/char/int_mail.cpp` | mail send／receive 封包 | 可承接成交物與款項，但須先做版本相容與重送防護 |

狀態：P2。台灣客戶端現行 Auction 封包相容性尚未完成實機驗證，因此寄售主方案為【資料不足，無法確認】。

## 官方 UI 素材覆蓋

已套用登入、創角、角色選擇、聊天傳送、NPC 對話、核取方塊、單選框及部分視窗背景。待完成所有功能視窗九宮格、分頁按下狀態、捲軸、裝備槽、技能按鈕與系統按鈕。進度維持 `in_progress`，逐窗通過手機與桌面玩家頁測試後才可標為完成。

3. P1：官方 UI 逐窗素材替換、各職業排行榜與公會頁。
4. P2：拍賣／寄售市場，僅在原生封包及交易一致性通過後開工。
