# RO 資料來源與核准制度

本文件是 RO Renewal 與 OpenKore 功能的唯一來源准入規則。

## 資料來源優先序

1. 鎖定版本的 rAthena 原始碼、`db/re`、`npc` 與 `doc`
2. 鎖定版本的 OpenKore 原始碼與官方文件
3. Gravity 官方公告、官方遊戲說明與可驗證的遊戲內資料
4. 具版本資訊、完整畫面證據及可重現步驟的實機測試
5. 多個獨立來源一致的社群實測
6. 專案推導，必須取得使用者核准

## 開發准入條件

任何內容進入正式遊戲資料前，必須通過以下檢查：

| 檢查 | 必要結果 |
| --- | --- |
| 名稱來源 | 有來源網址、檔案與版本 |
| 效果來源 | 有原文、資料列或可驗證摘要 |
| 公式來源 | 鎖定原始碼函式或可重現推導 |
| 數值來源 | 有可確認數值或使用者核准值 |
| 差異說明 | 列出網頁介面與 RO 客戶端的必要差異 |
| 測試 | 驗證效果、限制條件、資源消耗與重連行為 |

任一必要結果缺失時，內容只能標記為 `待查證` 或 `待使用者核准`，不得進入公開版本。

## 查無底層規則時

```text
確認固定來源未提供
→ 查詢 rAthena、OpenKore、Gravity 資料與實機行為
→ 建立可重現的輸入與輸出樣本
→ 提出規則候選與誤差
→ 取得使用者核准
→ 核准後才進入正式資料
```

## 現行稽核範圍

所有新工作從 `RO_SOURCE_BASELINE.md` 指定版本開始。新增職業、技能、怪物、道具、地圖、任務、NPC、掉落、轉職與掛機功能時，先查核 rAthena 與 OpenKore 是否已有原生能力，再決定重用或補接。

下一批需要稽核的資料：

1. 初心者與各職業的基礎能力、HP、SP、負重與經驗表
2. STR、AGI、VIT、INT、DEX、LUK 衍生公式
3. 普通攻擊的命中、傷害、攻速、射程與元素流程
4. 怪物生成、索敵、追擊、攻擊、重生與掉落
5. 技能需求、詠唱、延遲、SP 消耗與傷害
6. 地圖可行走格、傳送點、卡普拉與路線權重
