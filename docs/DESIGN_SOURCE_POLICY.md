# RO 資料來源與核准制度

本文件落實來源真實性鐵律。

## 資料來源優先序

1. 已鎖定 commit 的 rAthena Renewal 原始碼與 `db/re` 資料
2. 已鎖定 commit 的 OpenKore 原始碼與官方文件
3. Gravity 官方更新說明與可確認的遊戲內資料
4. 有版本資訊、完整畫面證據及可重現過程的實機影片
5. 多個獨立來源一致的社群實測
6. 專案分析推導，必須等待使用者核准

## 開發准入條件

任何內容進入正式遊戲資料前，必須通過以下檢查：

| 檢查 | 必要結果 |
| --- | --- |
| 名稱來源 | 有來源網址、檔案與版本 |
| 效果來源 | 原文、資料列或可驗證摘要 |
| 公式來源 | 鎖定原始碼函式或可重現推導 |
| 數值來源 | 可確認數值或使用者核准值 |
| 差異說明 | 列出 Web 掛機介面與 RO 客戶端的必要差異 |
| 測試 | 驗證效果、限制條件與資源消耗 |

任一必要結果缺失時，該內容只能留在研究文件，狀態為 `待查證` 或 `待使用者核准`。

## 查無底層公式時

```text
確認固定來源未提供
→ 搜尋官方說明、實機影片與玩家實測
→ 建立可重現的輸入與輸出樣本
→ 提出公式候選與誤差
→ 向使用者請求核准
→ 核准後才進入正式資料
```

## 現有內容稽核

Alpha 0.21 以前的 PoE 與火炬資料已失效，不得移植到 RO 模擬核心。新內容只能從 `RO_SOURCE_BASELINE.md` 指定的版本開始建立。

下一批需要稽核的資料：

1. 初心者的基礎能力、HP、SP、負重與經驗表
2. STR、AGI、VIT、INT、DEX、LUK 衍生公式
3. 普通攻擊的命中、傷害、攻速、射程與元素流程
4. 怪物生成、索敵、追擊、攻擊、重生與掉落
5. 技能需求、詠唱、延遲、SP 消耗與傷害
6. 地圖可行走格、傳送點與路線權重
