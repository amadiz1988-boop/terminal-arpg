# 公開版本壓力測試流程

## 目的

每次發布都要證明玩家能從新角色開始，實際殺怪、取得經驗、收到掉落、累積通貨、成長並持續遊玩。結算函式有回傳值不等於玩家已收到獎勵，因此兩者分開驗證。

## 一鍵發布門檻

執行 `npm run test:release`。只有最後輸出 `RELEASE_GATE_PASS` 才能進入公開流程。

這個命令依序執行：

1. 規則與回歸測試。
2. 5,000 張地圖結果壓力測試，涵蓋 T1 至 T5 與 1,000 個種子。
3. 1,000 組逐殺獎勵守恆測試，驗證即時取得總和等於地圖原始獎勵。
4. 1,000 張地圖的帳號加速模擬，檢查養成、通貨、地圖三換一、數值溢位與卡死。
5. 程式靜態檢查。
6. 正式環境建置。
7. 390×844 手機畫面流程，從新角色選職、啟動任務到實際擊殺，確認 EXP、裝備、通貨、戰鬥中換裝與戰力重算。
8. 小地圖驗證真實移動軌跡、投射物、受傷閃爍，以及 150% 至 200% 縮放操作。

## 極端狀態覆蓋

每次修改相關系統時，測試必須涵蓋以下邊界：

| 系統 | 必測狀態 |
| --- | --- |
| 戰鬥 | 魔力耗盡、普通攻擊接手、死亡、首領、暫停與繼續 |
| 獎勵 | 第一隻怪、普通怪無裝備掉落、高價值怪掉落、首領補齊、總量守恆 |
| 成長 | Lv.1 零點、升級給點、重置、戰鬥中即時重算 |
| 物品 | 空背包、99 件、100 件、自動分解、倉庫、上架鎖定 |
| 經濟 | 零通貨、最大批次兌換、打造失敗不扣款、購買時背包已滿 |
| 地圖 | T1 無限、T2 以上耗盡、三換一、連刷、1,000 圖不中斷 |
| 介面 | 390px 手機、桌面、無橫向溢出、移動軌跡、投射物、受傷閃爍、縮放、無主控台錯誤 |

## 公開後驗證

部署成功後，把 `QA_URL` 指向公開網址，再執行 `npm run qa:ui`。公開站必須再次通過選職、開打、擊殺、經驗與掉落入帳。公開後驗證失敗時，該版本立即標記為失敗並停止宣告完成。

## 報告格式

每次交付只記錄四項：

- 自動測試總數與通過數。
- 壓力測試地圖與種子數量。
- 手機玩家流程結果。
- 公開站版本與公開後驗證結果。

這個格式能減少重複敘述與 Token，同時保留發布判定所需證據。
