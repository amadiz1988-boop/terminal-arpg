# RO 測試角色與公開資料隔離

## 目的

功能測試使用專用角色隔離路線、NPC、裝備、技能與補給問題，避免測試資源污染玩家養成、排行榜、公會與募資展示資料。

## 永久規則

- `jobtest_*` 與 `gate2_*` 帳號在 `web_account_flags.is_test=1` 持久標記。
- 測試帳號排除各職業排行榜、總榜、公會搜尋、公會推薦、公開在線人數、成就排行與投資展示統計。
- 玩家 API 沒有生成等級、能力、HP、Zeny、物品、技能、職業或任務狀態的入口。
- 測試資料只經伺服器端測試路徑準備。測試結束必須停止該測試 worker。
- 玩家角色自行完成 Base／Job、基本技能、Zeny、裝備與物品養成。只有產品明確跳過的原始流程獎勵可以依固定來源補發。

## 測試資源準備

長距離路線測試可設定高 Base Level、VIT、AGI、DEX、HP、SP、Zeny，以及路線需要的原廠物品。這些數值只用來排除無關的死亡與資源不足，驗收結果不得作為戰鬥平衡證據。

養成流程測試先完成真實擊殺，確認索敵、攻擊、掉落、Base／Job EXP 增加、需求 EXP、補給及無死亡續跑。證據成立後，可由本機測試命令檔與 rAthena 管理指令將隔離測試角色補到下一個驗收門檻，避免重複等待已證明正常的經驗累積。加速事件必須寫入任務 Log，普通玩家介面不得呼叫。

轉職測試仍必須維持以下真實條件：

- 初心者職業。
- Job Lv.10。
- 基本技能 Lv.9。
- 原始 rAthena NPC 對話、職業變更、贈品與伺服器封包。

## 玩家原始獎勵

鎖定版 rAthena Renewal 的初心者訓練流程發放 30 張 `Warp_Free_Ticket`，物品 ID 7060。網頁創角刻意跳過訓練場，因此每名網頁角色只補發一次 30 張卡普拉傳送點免費利用券，並由 `web_character_grants` 記錄，防止重複補發。

## 驗收流程

1. 確認帳號測試旗標與公開資料排除條件。
2. 以伺服器端隔離方式準備本次測試所需強度與資源；需驗證自然成長時先取得真實戰鬥與經驗證據，再加速到下一門檻。
3. 由 OpenKore 使用原生指令、設定、MapRoute 或 NPC 流程。
4. 由實際玩家頁面點擊操作，記錄地圖轉換、NPC 對話與資源消耗。
5. 由 OpenKore 快照與 rAthena／MariaDB 交叉確認結果。
6. 確認測試 worker 停止，玩家與四名展示角色維持原狀。

## 2026-09-11 實例紀錄

- 魔法師測試角色曾在 `mjolnir_07` 被 Flora 擊倒，促成死亡重生續跑與危險地圖權重。
- 弓箭手測試角色曾在 `pay_fild04` 被 Mastering、Deviling 擊倒。其後改採 OpenKore `Task::CalcMapRoute` 與卡普拉免費券，去程直接 `prontera → payon`。
- 弓箭手第一次卡普拉回程已實際消耗第二張券；測試器在地圖封包先於背包封包抵達時誤讀為 0，現改為等待背包快照就緒後再驗證。
- 建表後共有 14 個測試帳號旗標，已知 `jobtest_*`／`gate2_*` 漏標數為 0；此數字是當次本機快照，後續以查詢結果為準。
