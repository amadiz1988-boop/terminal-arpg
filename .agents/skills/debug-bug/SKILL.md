# Debug Bug

依序完成以下流程：

1. 重現問題並蒐集錯誤訊息、stack trace、輸入、環境與可觀察症狀。
2. 以 stack trace、測試名稱或症狀定位責任模組與最可能的資料流。
3. 只讀取定位所需的相關檔案、測試與 source of truth；停止無目的全 repo 掃描。
4. 做最小修正，保留既有契約與資料，避免順手重構。
5. 先跑能重現問題的測試，再跑直接相關的回歸測試；依變更範圍補做 lint 或 build。
6. 將原因、修正、驗證命令、結果與仍存在的限制記錄到 `docs/CURRENT_STATUS.md` 或對應稽核文件。
7. 檢查差異只包含本次除錯，回報證據後停止。

若無法重現，記錄已嘗試的輸入與觀察結果，不以猜測替代原因；若需要改變產品規則，先停在明確的決策點。
